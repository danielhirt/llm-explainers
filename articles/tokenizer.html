Section 1 · The splitter

Text becomes IDs

Before a model can predict anything, the text has to become numbers. The unit of exchange is the token: a chunk of text that maps to one integer ID in a fixed vocabulary. A token is usually a word, part of a word, or a piece of punctuation. Whole words would need a vocabulary with millions of entries and would still miss new words. Single characters keep the vocabulary tiny but stretch every sentence into a long, expensive sequence. Tokens sit in between: common strings get their own entry, and rare strings break into smaller pieces.

Type below and watch the cut. Each chip is one token; ␣ marks a leading space, which belongs to the token. Click any chip to see its ID and how the tokenizer assembled it.

Notice two things. Common English words from the corpus come out as single tokens. Anything the tokenizer never saw during training, like German, digits, or code, shatters into small pieces. The same amount of text then costs more tokens. That is not a bug. The cut shows you what the training data looked like.

Section 2 · The vocabulary

Where the vocabulary comes from

Nobody sits down and writes a token list. An algorithm called byte-pair encoding learns the vocabulary from data. The whole algorithm fits in one sentence: start with single characters, count every adjacent pair in the corpus, glue the most frequent pair into a new token, and repeat. The ordered list of glue operations, called merges, is the tokenizer. To split new text later, the tokenizer replays the same merges in the same order.

The machine below runs byte-pair encoding for real on a small corpus written for this page. Step through it and watch character soup turn into words. Early merges pick up gluey letter pairs like th and in; later merges assemble whole common words. Turn on quiz mode to guess which pair merges next before the machine does.

Every tokenizer you ever used, including the one in front of your favorite chat model, came from exactly this process. The only difference is scale: terabytes of text and a few hundred thousand merges instead of 3 KB and a couple hundred. The consequences are identical: whatever was common in the training data becomes cheap, and everything else becomes expensive.

Section 3 · The counting game

Guess the cut

Token counts are not trivia. Context windows are measured in tokens, and API bills are measured in tokens. A model's sense of "how long is this text" is measured in tokens too. People who work with models daily still guess counts badly, because the cut follows the training data, not your intuition about words.

Section 4 · The predictor

Predicting the next token

Once text is IDs, the model's entire job is one question asked over and over: given the tokens so far, what comes next? The answer is a probability for every token in the vocabulary, never a single token. Something downstream picks one.

This page's predictor is deliberately primitive: it counts which token followed which pair of tokens in the corpus, and turns the counts into probabilities. A real model replaces the counting with a transformer that holds billions of learned weights. The transformer lets the model use the whole context instead of the last two tokens. The shape of the interface is identical, and that is the point: context in, distribution out.

Now race it. The sentence below was held out of the corpus. At each position, you and the predictor both pick the next token from four candidates. Then the page reveals the true token. The predictor only counts. See if reading the actual context lets you beat it.

Section 5 · The dice

Temperature and the dice

The distribution is not the output. Something has to pick one token from it, and how you pick changes everything about how the text feels. Greedy decoding always takes the single most likely token. It is safe and repetitive; run it long enough and it walks into loops. Sampling proportionally to the probabilities adds variety and risk.

Temperature reshapes the distribution before the draw. Below 1 it sharpens the peaks, so likely tokens become even more likely. Above 1 it flattens everything toward a uniform lottery. At 0 it collapses to greedy decoding. Top-k is a second guardrail: throw away all but the k most likely tokens before the draw.
