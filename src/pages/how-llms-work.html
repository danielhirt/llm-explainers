2 of 5 · The machine

How a language model turns text into the next token

A large language model (LLM) reads tokens and predicts one token that can come next. It adds that token to the text and runs again. Everything else in the machine exists to make that one prediction useful.

Section 1 · Lifecycle

A model is built once, then used many times

In one sentenceTraining sets the model's numbers. A request reads those frozen numbers to produce one token at a time.

The build path collects text, creates a tokenizer, and adjusts billions of learned numbers called weights. Training saves the finished weights in a checkpoint.

The run path cuts a prompt into tokens, reads the frozen checkpoint, chooses one next token, and repeats. A normal request does not change the checkpoint.

Section 2 · Corpus

The model learns from a selected dataset

In one sentenceA model can learn only the patterns that its training data contains.

The build path starts with text: web crawls, books, code, and papers. None of it is ready to use. Data pipelines extract the usable text, remove boilerplate and near-duplicates, apply quality and safety filters, and choose a mix of languages and domains. Then they split the documents into training examples. These choices decide which patterns the model can see, and how often.

Engineers usually train the tokenizer (Section 3) on a representative sample of the corpus. Then they use that frozen tokenizer to encode the much larger training set. The FineWeb paper publishes concrete filtering and deduplication experiments. Reports on proprietary models often disclose only part of the data recipe.

Accuracy check

Documents do not flow straight into a transformer. They become packed arrays of token IDs, usually with a boundary token where one document ends and the next begins. Figure 2 shows storage, shuffling, packing, and distributed loading as one line.

Section 3 · Tokenization

Text becomes a sequence of vocabulary addresses

In one sentenceThe tokenizer cuts text into pieces and gives each piece a number.

A neural network computes with numbers, so text must become numbers first. A tokenizer cuts a string into pieces from a fixed vocabulary and returns their integer token IDs. A common word can be one token. A rare name can split into several pieces or single bytes. Spaces, punctuation, and fragments of code can be tokens too. To try it yourself, open Tokens are the meter.

Show the tokenizer notation
Tokenizer outputt1, …, tT = Tokenize(s),   ti ∈ {0, …, |V| − 1}

s is the input string, T is its token count, and |V| is the vocabulary size. A token ID is an address. Its numeric value carries no distance or meaning.

Byte-pair encoding (BPE) and Unigram tokenization choose the vocabulary with different algorithms. SentencePiece describes both in a language-independent system that trains from raw sentences. Production tokenizers often add byte fallback, so any character can be encoded, and special control tokens.

Keep the artifacts separate

Tokenizer training chooses a fixed vocabulary. Pre-training later learns the embedding vectors and the transformer weights. After pre-training starts, a change to the token-to-ID map breaks the embedding rows that belong to those IDs.

Section 4 · Embeddings and position

Each token ID selects a learned vector

In one sentenceEach token ID picks one row of numbers that the model can compare and change.

A token ID is only a catalog number. The embedding table gives it content: one learned row per vocabulary entry. A lookup of token ti returns that row, a vector of dmodel numbers. You can picture a vector as a point in space. During training, tokens that appear in similar contexts move toward nearby points. The vector from the lookup is the model's starting working state, its hidden state, at position i.

Show the embedding lookup
Embedding lookupx(0)i = E[ti],   E ∈ ℝ|V| × dmodel

The bracket is a row lookup, not a search by meaning. Pre-training adjusts every row that the training text uses, through gradient descent.

The network also needs word order: "dog bites man" and "man bites dog" contain the same tokens. Many current models use rotary position embeddings (RoPE). In each attention layer, RoPE rotates pairs of coordinates in every query and key by an angle that grows with the token's position. After the rotation, the attention score between two tokens depends on the distance between their positions, not on where they sit in the text. RoPE does not add a vector to the embedding.

Show the RoPE notation
RoPE, simplifiedq′i = R(i)qi,   k′j = R(j)kj

R(i) rotates each pair of coordinates by the angle i·θ, where each pair has its own frequency θ. The dot product q′i · k′j then depends on the offset i − j. See RoFormer.

A real hidden state can have thousands of coordinates. Nearby vectors suggest similar use, but the values in Figure 4 are examples, not measurements from a trained model. After the first layer, a hidden state also carries context, so it is not a fixed word meaning.

Section 5 · Transformer block

Attention mixes positions; the MLP transforms each one

In one sentenceAttention pulls useful context from earlier tokens, then the MLP updates each token's working state.

A transformer is a stack of nearly identical blocks. Each block makes two moves. Attention lets every position read from earlier positions, so the state for "bank" in "the river bank" can take in "river". The MLP, a small feed-forward network, then reworks each position on its own. The rest of this section states both moves exactly.

Let X hold the hidden states of a sequence. One attention head makes three linear projections. Queries describe what each position looks for. Keys describe what each position offers for matching. Values carry the information that attention mixes.

Show the attention math
One causal attention headQ = XWQ,   K = XWK,   V = XWV
A = softmax(QKT / √dhead + Mcausal)
Attention(X) = AV

Row i of A holds the weights that update token i, and they sum to 1. Mcausal[i, j] is −∞ when j > i, so softmax gives later positions a weight of zero. The division by √dhead keeps the dot products in a stable range.

Several heads run in parallel. The block combines their results, and an output projection returns them to the model width. Grouped-query attention lets heads share keys and values to reduce memory traffic. Each query still obeys the causal mask.

A modern block normalizes before each sublayer and adds the result back to a residual path:

Show the block equations
One decoder block, schematicx ← x + Attention(RMSNorm(x))
x ← x + MLP(RMSNorm(x))

The residual path keeps the current state while each sublayer writes an update. A SwiGLU-style MLP expands each position, gates it, then projects it back to dmodel. Models differ in their exact normalization, gating, and bias choices.

Attention Is All You Need introduced the encoder-decoder transformer, with normalization after each sublayer. Modern decoder-only models often use RMSNorm, RoPE, gated MLPs, and grouped-query attention. OpenELM documents one compact example.

Section 6 · Pre-training

Every position supplies a training target

In one sentenceThe model guesses each next token, measures each error, and adjusts its weights.

Pre-training sets the numbers in the block. It is a guessing game, graded at every position. The model reads corpus text, and at each position it must give a high probability to the token that comes next. The causal mask stops it from reading later tokens, so training can grade all positions of a sequence at the same time. This setup is called teacher forcing.

Show the training loss
Next-token model and cross-entropy losspθ(t1:T) = ∏i=1T pθ(ti | t<i)
L(θ) = −(1/N) Σi log pθ(ti | t<i)

If the model gives the actual next token a probability of 0.80, that position adds −log(0.80) ≈ 0.223 to the loss. A probability of 0.05 adds about 2.996. A confident mistake costs more.

Backpropagation computes the gradient of the batch loss: for each weight, how a small change raises or lowers the loss. An optimizer such as AdamW keeps running statistics of these gradients and uses them to make a small update. Large runs spread this work across many accelerators.

Show the optimizer step
Optimizer step, schematicθk+1 = AdamW(θk, ∇θL, η)

θ holds the embeddings, the attention projections, the MLP weights, the normalization scales, and the output projection. η is the learning rate. This schematic leaves out AdamW's moment estimates and weight decay.

The GPT-3 paper is a concrete reference for decoder-only training. Chinchilla found that, for a fixed compute budget, models did better when parameter count and training tokens grew together. That result is an empirical recipe for the regime it studied, not a law for every model or dataset.

After pre-training

Instruction tuning and preference training adjust the checkpoint again with curated examples and human or AI preferences. They shape behavior. Generation still uses the same forward pass, one token at a time. See InstructGPT for an influential example.

Section 7 · Generation

The last hidden state becomes one score per token

In one sentenceThe model scores every possible next token, picks one, adds it to the text, and runs again.

At request time, the frozen tokenizer encodes the prompt. The frozen transformer runs the same forward pass as in training, with no update afterward. A final normalization and an output projection turn the last hidden state into one logit, an unnormalized score, for every vocabulary entry. Some models reuse the embedding table as this output matrix.

Show logits and temperature
Logits and temperature-scaled probabilitiesz = WUhT + b
pi = exp(zi/τ) / Σj exp(zj/τ)

WU is the output (unembedding) matrix; many models have no bias b. A lower temperature τ moves probability toward the largest logits. A higher τ flattens the distribution. Greedy decoding takes the largest logit. Top-k and top-p sampling first cut the candidate list, then sample from what remains.

The loop appends the chosen token, and decoding repeats. In the first pass over the prompt, called prefill, the model computes keys and values for every prompt token. A KV cache keeps them. Each later step then computes only the new position and attends over the cached keys and values. Systems such as PagedAttention manage that cache efficiently.

What stays fixed

The checkpoint does not learn from a request. The KV cache is temporary state for one sequence, not memory. Randomness enters only through the decoding rule. With fixed token IDs and weights the forward pass is deterministic in principle; in practice, batching and floating-point order can change results slightly.

Section 8 · Complete pass

Put the whole machine back together

In one sentenceThe build path makes reusable artifacts once; the run path reads them once per generated token.

The build path turns a corpus into a tokenizer and, through pre-training, into a checkpoint. The run path uses that frozen tokenizer and checkpoint to turn a prompt into one selected token. The token extends the context, and the next step reads it too.
